# 开发与发布

## 环境与结构

使用 Windows x64、.NET 10 SDK；SDK 选择规则见 `global.json`。WPF 主程序不能在 Linux 或 macOS 上运行。

| 目录 | 内容 |
| --- | --- |
| `src/SVNRevDesk.Core` | SVN 调用、状态分类、文件操作、备份、内置工具。 |
| `src/SVNRevDesk.Desktop` | WPF 界面、设置、交互、文件预览与系统托盘。 |
| `tests/SVNRevDesk.IntegrationTests` | 使用真实临时 SVN 仓库的集成测试，可执行程序形式。 |
| `tests/SVNRevDesk.UiSmokeTests` | WPF 控件行为及离屏渲染检查，可执行程序形式。 |
| `vendor` | 固定版本的第三方工具、许可、源码及 SHA-256 清单。 |
| `build` | 工具验证、打包与嵌入的 MSBuild 任务。 |
| `scripts` | 发布打包脚本。 |

## 构建和测试

```powershell
dotnet build SVNRevDesk.slnx -c Release
```

集成测试需要额外安装包含 `svnadmin.exe` 的 SVN 分发，并将其 `bin` 目录加入 PATH（例如 SlikSVN）。主程序运行不需要这个管理工具。

```powershell
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- .build/check/integration
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --ignore .build/check/ignore
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --file-move .build/check/file-move
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --file-transfer .build/check/file-transfer
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --revisions .build/check/revisions
dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --file-management .build/check/file-management

dotnet run --project tests/SVNRevDesk.IntegrationTests -c Release -- --search-index .build/check/search-index
```

每次执行请使用尚不存在的测试目录；测试会创建仓库及工作副本，不连接业务服务器。测试采用自定义可执行程序，请使用 `dotnet run`，而不是 `dotnet test`。

WPF 检查需要适合桌面操作的 Windows 环境，以及包含受控 `equal.txt`、未受控文件和 `nested/child.txt` 的测试工作副本；未受控文件名称应排在受控文件之后：

```powershell
dotnet run --project tests/SVNRevDesk.UiSmokeTests -c Release -- D:\TestWorkingCopy .build/check/ui
dotnet run --project tests/SVNRevDesk.UiSmokeTests -c Release -- D:\TestWorkingCopy .build/check/sessions --sessions
dotnet run --project tests/SVNRevDesk.UiSmokeTests -c Release -- D:\TestWorkingCopy .build/check/revision-picker --revision-picker
dotnet run --project tests/SVNRevDesk.UiSmokeTests -c Release -- D:\TestWorkingCopy .build/check/file-management-ui --file-management

# 本地优先浏览、慢网、取消和缓存回归；此项自行创建受控目录，不需要真实工作副本。
dotnet run --project tests/SVNRevDesk.UiSmokeTests -c Release -- . .build/check/browsing-ui --browsing
```

部分检查涉及剪贴板或外部工具窗口，建议在专用测试会话中执行。截图使用实际 WPF 控件离屏渲染。

## 本地发布

本地和 GitHub 发布统一使用三段式版本号，不再使用日期时间版本号。版本规则如下：

- 本地开发从最近正式版的下一个修订号开始，例如正式版 `1.2.0` 之后使用 `1.2.1`，后续本地迭代使用 `1.2.2`、`1.2.3`。
- GitHub 正式发布递增中间一段并将末位归零，例如下一次发布为 `1.3.0`，标签为 `v1.3.0`。
- 发布后本地开发从 `1.3.1` 继续。每次本地迭代修改 `src/SVNRevDesk.Desktop/SVNRevDesk.Desktop.csproj` 中的默认 `Version`；同一版代码重复编译时保持版本号不变。
- 打包脚本通过 `ReleaseVersion` 覆盖版本号，GitHub 工作流从标签取得此值；应用内显示和 EXE 产品版本均使用同一个版本号。

```powershell
pwsh ./scripts/Publish-Release.ps1 -Version 1.3.0
```

输出位于 `artifacts/releases/v1.3.0/`，包含自带运行时版、不带运行时版 ZIP 以及 `SHA256SUMS.txt`。两种版本功能相同，发布版本号写入应用版本信息。

可用 `-Variant WithRuntime` 或 `-Variant WithoutRuntime` 单独生成一种。脚本使用独立、全新的发布目录，避免将个人配置、认证缓存和备份混入包内；已存在同名目录时会停止。

## GitHub 自动化

- `ci.yml`：推送 `main` 或提交 PR 时执行 Release 构建，以及 `--portable-ci` 真实仓库测试（状态、更新、勾选提交、备份、移动、忽略、导出、Office 文档、持久化搜索索引、批量改名与内嵌工具验证）。搜索索引专项覆盖无网络查询、增量更新、离线重启、本地监听、切换映射、损坏缓存及取消。此套件使用 ASCII SVN 目标，兼容 GitHub 英文 Windows 托管环境；上面的完整及专项套件保留中文路径覆盖，需在兼容中文的系统区域设置下执行。
- `release.yml`：推送 `v主版本.次版本.修订号` 标签后，构建、测试、生成两种 ZIP 及校验文件，发布 GitHub Release。
- 发布说明优先读取 `docs/releases/v版本号.md`；没有对应文件时使用 GitHub 自动生成的说明。
- 也可手动运行发布工作流并输入已存在的版本标签。

先更新版本说明和更新日志并通过验证，再提交和推送对应标签。GitHub 工作流使用仓库自带的 `GITHUB_TOKEN`，无需提交个人访问令牌。

## 第三方分发

不要移除 `vendor` 内许可证和 WinMerge 对应完整源码。升级第三方工具时，应同步 `.files`、`.sha256.json`、声明与依赖，并运行内嵌工具验证。详见 [第三方声明](../THIRD-PARTY-NOTICES.md)。
